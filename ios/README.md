# iOS app — Construction Calc

SwiftUI front-end for the `calc-core` engine, via the `calc-uniffi`
bindings. **These Swift sources are written and committed off-Mac; they
compile once the `CalcEngine.xcframework` is built and linked.** Nothing
here has been run through a Swift compiler yet — treat the first build as
a shakedown and expect to nudge a few things in Xcode (where you get live
previews and real error messages).

## Layout

```
ios/
├── README.md                       ← this file
├── ConstructionCalc/               ← hand-written app sources (committed)
│   ├── ConstructionCalcApp.swift   ← @main entry point
│   ├── CalculatorViewModel.swift   ← @Observable wrapper over the engine
│   ├── Model/
│   │   ├── KeypadModel.swift        ← button grid (mirrors Keypad.svelte)
│   │   ├── FormatOption.swift       ← format strip (mirrors FormatStrip.svelte)
│   │   ├── Preferences.swift        ← UserDefaults (mirrors preferences.ts)
│   │   └── HelpText.swift           ← long-press help (mirrors help.ts)
│   └── Views/
│       ├── CalculatorView.swift     ← root screen
│       ├── DisplayView.swift
│       ├── FormatStripView.swift
│       ├── KeypadView.swift
│       ├── TapeView.swift
│       ├── HelpOverlayView.swift
│       └── PreferencesView.swift
├── CalcEngine.xcframework/         ← GENERATED by build-ios.sh (gitignored)
├── headers/                        ← GENERATED (gitignored)
└── Sources/CalcEngine/             ← GENERATED CalcEngine.swift (gitignored)
```

The `CalcEngine.swift`, `headers/`, and `*.xcframework` are produced by
`scripts/build-ios.sh` and are gitignored — they're build outputs, not
source.

## First build (on the Mac)

1. **Build the engine framework** from the repo root:
   ```bash
   bash scripts/build-ios.sh
   ```
   This installs the iOS Rust targets, builds the three slices, generates
   the Swift bindings, and assembles `ios/CalcEngine.xcframework`.

2. **Create the Xcode project.** New → App, SwiftUI, name
   `ConstructionCalc`, bundle id `com.nuniesmith.constructioncalc`,
   minimum deployment iOS 17.0. Save it inside `ios/` (it can sit beside
   the `ConstructionCalc/` sources folder).

3. **Add the engine.**
   - Drag `ios/CalcEngine.xcframework` into the project navigator; in the
     app target's *General → Frameworks, Libraries, and Embedded Content*
     set it to **Embed & Sign**.
   - Add the generated binding to the target's sources: drag
     `ios/Sources/CalcEngine/CalcEngine.swift` into the project (check
     "Add to target").

4. **Add the app sources.** Delete the stub `ContentView.swift` Xcode
   created, then drag the `ios/ConstructionCalc/` folder (the one with
   `Model/` and `Views/`) into the project, "Create groups", add to
   target. Keep the Xcode-generated `ConstructionCalcApp.swift` OR replace
   it with the committed one — they're equivalent; don't end up with two
   `@main` structs.

5. **Build & run** on a simulator. Smoke test:
   - Type `5`, tap `Feet` → display shows `5'`
   - `5 [Feet] 6 [Inch] + 2 [Feet] 7 [Inch] =` → `8' 1"` (at 1/16")
   - Tap the `1/4"` chip → the running result rounds to the nearest 1/4"

## Notes

- **`@Observable` + iOS 17.** The view model uses the `@Observable` macro;
  the root view holds it with `@State`. If you target below iOS 17, swap to
  `ObservableObject` + `@StateObject`.
- **`panic = "abort"`.** See the top-level `todo.md` §3.1 — if you hit a
  hard crash that should have been a caught error, that's the abort
  profile, and the fix is an iOS-specific `panic = "unwind"` profile.
- **Layout parity.** `KeypadView` mirrors the web `Keypad.svelte` 6-column
  grid faithfully. On a phone you may prefer the 5-column CMPro layout —
  that's a cosmetic tweak best done in Xcode with live previews; the
  button → `KeyEvent` mapping stays identical either way.
